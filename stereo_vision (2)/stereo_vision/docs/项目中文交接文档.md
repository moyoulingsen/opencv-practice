# 双目标定与极线矫正中文交接文档

本文档用于把当前 `stereo_vision` 项目完整交接给后续做视觉算法和部署的同学。

适用对象：

- 需要读取双目标定参数的视觉算法同学
- 需要把双目极线矫正接入实时视频链路的同学
- 需要在 `RK3588` 上部署双目预处理的同学

## 1. 项目目标

本项目完成了以下工作：

- 基于棋盘格完成双目标定
- 输出左右单目内参和双目外参
- 输出极线矫正所需参数与映射关系
- 提供实时极线矫正脚本
- 提供角点调试、极线调试、`alpha` 扫描等辅助脚本

当前已经确认可用的一版标定结果来自 `33` 张原始未分割双目图像，使用简单 `pinhole` 模型联合求解得到。

## 4. 当前推荐的极线矫正使用方式

### 4.1 推荐运行方式

对于实时链路，当前推荐：

- 标定源：`stereo_vision/data/outputs_camera_roll_33_simple_joint`
- 运行时 `alpha`：`0.20`
- 主点模式：`centered principal point`（居中主点）

原因：

- `alpha=0.0` 裁切太重，视角损失大
- `alpha=1.0` 原生 OpenCV 输出对你这台相机看起来会明显“缩成一团/偏到角上”
- `alpha=0.20 + 居中主点` 是当前比较平衡的方案，能尽量保留左下角内容，同时保持较好的极线对齐

### 4.2 关于分辨率是否变化

极线矫正不会改变每眼图像的输出像素尺寸：

- 输入左图：`1280 x 720`
- 输出左图：`1280 x 720`
- 输入右图：`1280 x 720`
- 输出右图：`1280 x 720`

但会改变：

- 画面几何关系
- 视场保留比例
- 黑边/裁切分布
- 有效内容在画面中的位置

所以要区分：

- `像素尺寸没变`
- `画面内容变了`

## 6. 标定与极线矫正的工作原理

### 6.1 标定阶段做了什么

1. 在原始左右图上检测棋盘角点
2. 求左右单目内参和畸变
3. 联合求双目外参 `R/T`
4. 用 `stereoRectify` 生成极线矫正参数
5. 生成 `initUndistortRectifyMap` 所需的参数并输出

### 6.2 运行阶段做了什么

运行时不会重新标定，也不会重新算角点。

运行时只做：

1. 读取一帧 `2560 x 720` 拼接原始图
2. 切分成左右 `1280 x 720`
3. 对左右图各做一次 `cv2.remap(...)`
4. 输出矫正后的左图、右图或预览图

所以实时链路里最重要的是：

- 离线标定好
- 启动时生成 map
- 每帧只做 remap

## 9. RK3588 部署建议

### 9.1 能不能实时做

能。

只要运行时只做：

- 左右切分
- 左图 remap
- 右图 remap

这部分是比较轻的。

当前在开发机上的只读测速结果说明：

- 只做双目 remap：约 `2.18 ms / 双目对`
- 做拆分 + remap + 拼接预览 + 画线：约 `4.55 ms / 双目对`

因此：

- 你看到的 GUI 预览帧率低，不代表几何变换本身慢
- 真正部署到 `RK3588` 时，只做运行时矫正是现实可行的

### 9.2 低延迟建议

对 `RK3588` 建议：

- 优先用 `C++` 实现实时版本
- 启动时一次性生成 remap 表，不要每帧重建
- 使用 `cv::convertMaps` 生成更快的固定点 map
- 如果后续要做立体匹配，单独评估那一段的算力，不要把 rectification 和 stereo matching 混为一谈
